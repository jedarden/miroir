## Implementation Details

### Cache Hit Flow
1. Request received → Query canonicalized
2. Cache key generated (index + canonical query + settings version)
3. Cache lookup attempted
4. **On Cache Hit:**
   - Metrics: `inc_result_cache_hits()`
   - Logging: `info!` with duration tracking
   - Response: Cached data deserialized and returned
   - **Result**: No scatter-gather execution, no upstream calls
5. **On Cache Miss:**
   - Metrics: `inc_result_cache_misses()`
   - Logging: `debug!` for miss
   - Response: Proceed to scatter-gather execution
   - **Result**: Normal upstream calls to nodes

### Performance Benefits
- **Reduced Latency**: Cache hits skip entire scatter-gather phase
- **Reduced Load**: No upstream calls to Meilisearch nodes
- **Reduced Network**: No inter-node communication for cached queries
- **Observability**: INFO-level logging tracks cache effectiveness

## Technical Notes

### Logging Targets
- `miroir.search_cache_hit`: Regular search cache hits
- `miroir.multi_search_cache_hit`: Multi-search cache hits
- `miroir.search`: Regular scatter-gather search completion
- `miroir.search_multi_target`: Multi-target alias search completion

### Cache Invalidation
- TTL-based expiration (configurable, default 500ms)
- Settings version changes invalidate cache
- LRU eviction when `max_size` exceeded
- Cache disabled queries bypass all cache logic

### Multi-target Aliases
- Cache is bypassed entirely for multi-target aliases
- Each target may have different results
- Implemented via `resolved_targets.len() == 1` check
