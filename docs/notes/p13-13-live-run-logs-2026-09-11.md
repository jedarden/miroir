## Failure classification — 9×A + 1×B, all accounted, nothing unexplained

Counting rule first, because it trips people: a failed **test** is one entry
in the `failures:` list — 10 per run. Panic **lines** are 11 per run, because
acceptance_8 panics twice (its spawned task hits the assertion, then the
`handle.await.unwrap()` re-panics with `JoinError::Panic` wrapping the same
message). 10 failed tests and 11 panic lines are both correct counts.

- **Signature A — 9 tests per run** (acceptance_1 through acceptance_9), one
  primary panic each at that test's **first** search POST:
  - 05:52 run: test-file lines 508 / 622 / 738 / 858 / 959 / 1023 / 1068 /
    1135 / 1196 (columns :5, :9 or :13 matching the assert's indentation).
  - 05:22 and 04:56 runs: same nine tests at test-file lines 508 / 622 / 728 /
    794 / 868 / 932 / 977 / 1044 / 1105.
  - Verified against both pinned trees that each of those lines is the first
    `.status().is_success()` assert inside its test function — the failure
    really is the first search, not a later step of the test.
  - Plus acceptance_8's secondary re-panic (`JoinError::Panic(...)`) — one per
    run, same signature, counted inside acceptance_8's single failure.
- **Signature B — acceptance_10, one per run:** `Result::unwrap()` on `Err`
  "Failed to update settings on http://localhost:<ephemeral-port>: 405 Method
  Not Allowed" (test-file 1268:10 in the `8c1b2db` tree, 1177:10 in
  `fd1703f`). The settings PUT precedes acceptance_10's first search assert
  (first `is_success` assert in that function is test-file 1287 / 1196), so
  the test dies at setup and never reaches a search.

## Ephemeral node ports — NOT the fixed suite ports

acceptance_10's error message is the only place each run's ephemeral
Meilisearch testcontainer port appears:

| Run | Ephemeral node port |
|---|---|
| 05:52 | 33107 |
| 05:22 | 33077 |
| 04:56 | 33016 |

These are fresh per run. Do not confuse them with the suite's **fixed** ports
(proxy 17770, Meilisearch 9090) that the suite hard-binds elsewhere, and do
not treat a stale 33107/33077/33016 in a later rerun as a leak from these
captures.

Root-cause attribution was established on `miroir-1ec135a1` (children
`miroir-9ce8c5d7`, `miroir-10842a18`, `miroir-49ae723b`) and is restated here
as one line each, only to anchor the signatures: A = the suite POSTs the
Meilisearch-native path `/indexes/{uid}/search`, which the proxy has never
routed, so axum answers 404 with an empty body; B = `set_node_settings()` PUTs
settings, which the `getmeili/meilisearch:v1.8.3` nodes answer 405 (PUT→PATCH
flip). Nothing found during this classification contradicts that diagnosis.
